# Лабораторна робота 4 — докладна інструкція

## 0. Що в архіві

Три **готові, повні** проєкти (Vite + React + TypeScript): `lab4-guess`, `lab4-fruits`, `lab4-input`.
У кожному є `package.json`, конфіги TypeScript/ESLint, `index.html`, `src/main.tsx`, стилі та код завдання.
Немає лише `node_modules`, `dist` і `package-lock.json` — вони створюються командою `npm install`
(у лабораторній вимагається здати `package-lock.json`, тож не видаляйте його після встановлення).

## 1. Підготовка (один раз)

1. Встановіть Node.js (LTS) з https://nodejs.org та редактор коду (VS Code).
2. Відкрийте термінал і перевірте:
   ```
   node --version
   npm --version
   ```
   Обидві команди мають вивести номер версії.

## 2. Запуск кожного проєкту

Розпакуйте архів. Далі для **кожної** з трьох папок (`lab4-guess`, `lab4-fruits`, `lab4-input`):

```
cd lab4-guess        # потім lab4-fruits, lab4-input
npm install          # встановлює залежності, створює package-lock.json
npm run dev          # запускає сервер розробки
```

У терміналі з'явиться рядок `Local: http://localhost:5173/` — відкрийте цю адресу в браузері.
Зупинити сервер: `Ctrl+C`. Щоб запустити наступний проєкт, спершу зупиніть попередній
(або відкрийте окремий термінал — тоді порт буде 5174).

> Якщо хочете створити проєкти «як у методичці», можна виконати
> `npm create vite@latest lab4-guess -- --template react-ts` і лише замінити файли в `src/`
> файлами з цього архіву (для lab4-fruits і lab4-input — аналогічно).
> Тоді в `main.tsx` залишайте код шаблону.

## 3. Перевірка (самоперевірка з методички)

### Завдання 1 — `lab4-guess`
- Сторінка завантажилась — діалог **не** відкривається сам.
- «Почати» → prompt. Введіть `1` і `5` — приймаються, з'являється alert із двома числами.
- `0`, `6`, `2.5`, `abc` → alert «Потрібно ввести ціле число від 1 до 5».
- Порожній рядок і рядок із пробілів → «Ви не ввели число».
- «Скасувати» → нічого не відбувається, помилки в консолі немає.
- Після закриття alert знову натисніть «Почати» — генерується нове число.

### Завдання 2 — `lab4-fruits`
- На екрані три фрукти та «Всього фруктів: 3».
- Тимчасово додайте в `App.tsx` четвертий об'єкт `{ id: 4, fruitName: 'Банан' }` і перезавантажте
  сторінку (F5) → 4 елементи й «Всього фруктів: 4», при цьому `FruitsCounter.tsx` не змінювався.
- Тимчасово зробіть масив порожнім `[]` → «Всього фруктів: 0».
- Поверніть три початкові фрукти.

### Завдання 3 — `lab4-input`
- На початку Counter = 0, «Number of characters: 0».
- Decrease з нуля → `-1` і повідомлення «Counter can't be negative»; Increase до 0 → повідомлення зникає.
- Введіть `React` → одразу «Number of characters: 5».
- Submit → під формою `React`, сторінка не перезавантажується.
- Змініть поле на `React TS` → символів 8, але текст під формою залишається `React`, доки знову не натиснути Submit.
- Enter у полі працює як кнопка Submit.
- Порожнє поле або самі пробіли → повідомлення про помилку, попередній підтверджений текст не стирається.
- Кнопки лічильника не чіпають текст, а введення тексту не чіпає лічильник.
- Додатково: кнопка Reset скидає лічильник у 0; поле не приймає більше 50 символів, видно `N/50`.

## 4. Завершення роботи

У **кожному** проєкті (в окремому терміналі або після `Ctrl+C`):

Обидві команди мають завершитись без помилок. Якщо є помилки — див. розділ 6.

## 5. Що здавати

1. Три папки проєктів **без** `node_modules` і `dist`, але **з** `package.json` і `package-lock.json`
   (заархівуйте в zip).
2. Короткий опис запуску (можна скопіювати розділ 2 цього файлу).
3. Скриншоти: по кожному завданню — стартовий екран, результат, перевірка некоректного введення;

## 6. Типові проблеми

| Симптом | Що робити |
|---|---|
| `npm: command not found` | Перевстановіть Node.js, перезапустіть термінал |
| Порт зайнятий | Зупиніть інший `npm run dev` (Ctrl+C) |
| Не знайдено компонент | Перевірте шлях імпорту, регістр у назві файла, `export default` |
| Не знайдено `useState` | `import { useState } from 'react';` |
| Помилка про type-only імпорт | Використовуйте `import type { Fruit } from './types';` |
| Поле не редагується | Перевірте, що `onChange` оновлює стан |
| Форма перезавантажує сторінку | Потрібен `event.preventDefault()` в `onSubmit` |
| Кількість не змінюється | Не записуйте її константою, рахуйте через `.length` |

## 7. Як працює код (для пояснення на захисті)

**Завдання 1.** `handleClick` викликається React лише після кліку (`onClick={handleClick}`).
`prompt` повертає рядок або `null`, тому спочатку перевіряємо `null` (скасування), потім порожній рядок,
і лише потім `Number(...)`. `Number.isInteger` відсікає `NaN` і дробові числа. Стан не потрібен —
результат показується в `alert`.

**Завдання 2.** Стан `fruits` оголошено в `App` — найближчому спільному батькові `Fruits` і `FruitsCounter`
(підняття стану). Діти отримують масив через props і лише читають його. Кількість — похідне значення
(`fruits.length`), тому окремий стан не створюється і розсинхронізації бути не може.

**Завдання 3.** `count` — локальний стан `Counter`. `text` лежить в `App`, бо потрібен і полю (`TextInput`),
і лічильнику символів (`App`). `submittedText` та `error` потрібні лише `TextInput`, тому лишаються в ньому.
Поле кероване: показує `value` з props, а при введенні викликає `onTextChange` (це `setText` з `App`).
`onSubmit` форми ловить і кнопку, і Enter; `preventDefault()` забороняє браузеру перезавантажити сторінку.

## 8. Відповіді на контрольні питання

1. `onClick={handleClick}` передає функцію, яку React викличе після кліку. `onClick={handleClick()}`
   викликає її під час рендеру, а в `onClick` потрапляє результат виклику (`undefined`) — це помилка.
2. `prompt` повертає рядок (що ввів користувач) або `null` (якщо натиснули «Скасувати»). Введення може бути
   порожнім, текстом, дробом чи виходити за діапазон, тому його перевіряють і перетворюють на число
   **до** порівняння; інакше порівняння буде некоректним.
3. `Math.floor(Math.random() * 5) + 1`. `Math.random()` дає [0; 1), множення на 5 і `floor` — цілі 0–4,
   `+ 1` зсуває до 1–5.
4. `useState` зберігає значення між рендерами; виклик функції оновлення змушує React перерендерити
   компонент. Форма `previous => previous + 1` обчислює нове значення з актуального попереднього,
   тож кілька оновлень поспіль не губляться.
5. Фрукти потрібні і списку, і лічильнику, тому стан піднято в їхній спільний батьківський `App`.
   Кількість не зберігають окремо, бо її можна обчислити з масиву; окрема копія могла б розійтись із ним.
6. Кероване поле — поле, значення якого повністю визначає стан React (`value` береться зі стану, а
   `onChange` його оновлює). `onTextChange` — prop-функція, через яку дочірній компонент повідомляє
   батьківському про новий текст, бо стан живе в батьківському.
7. Поточний текст (`text`) — те, що зараз у полі, змінюється при кожному символі. Підтверджений
   (`submittedText`) — копія, зроблена лише після коректного Submit; показується під формою.
8. `onSubmit` обробляє і клік по Submit, і Enter. `preventDefault()` скасовує стандартну поведінку форми —
   перезавантаження сторінки, яке скинуло б увесь стан.
9. TypeScript перевіряє типи на етапі розробки/збірки (наприклад, що в props передано `string`).
   Він не працює у браузері й не знає, що користувач введе під час роботи, тому валідація введення потрібна окремо.

## 9. Типові зміни на захисті

- **Діапазон гри 1–10:** у `lab4-guess/src/App.tsx` замініть `userNumber > 5` на `> 10`,
  `Math.random() * 5` на `* 10`, і тексти «1 до 5» на «1 до 10».
- **Додати фрукт:** у `lab4-fruits/src/App.tsx` додайте в масив `{ id: 4, fruitName: 'Банан' }` (унікальний `id`).
  Лічильник оновиться сам.
- **Крок лічильника 5:** у `Counter.tsx` замініть `previous + 1` на `previous + 5`, `previous - 1` на `previous - 5`.
- **Максимальна довжина 100:** у `TextInput.tsx` змініть `maxLength={50}` на `100` і `/50` на `/100`.
